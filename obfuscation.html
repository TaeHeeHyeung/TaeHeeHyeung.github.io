배경 — 구글 플레이 콘솔 경고

DEX 코드 최적화가 기준점 미만입니다. 다음 카테고리에서 비율을 개선하세요. 난독화(1%)
비율이 25% 미만인 앱 카테고리가 있으면 Google Play에서 앱의 공개 상태와 게시 기능이 영향을 받을 수 있습니다.

Android 개발자 문서 — 코드 최적화

중요하게 생각한 점

  • 유지보수: 미래의 코드 실수를 막기 위해 빌드 시 코드 체크 기능 추가
  • dontwarn 제거: 경고를 무시하는 기능이라 위험할 수 있어, 필요할 때만 추가
  • @Keep 어노테이션 사용
  • 에러 확인: mapping 파일 Play Console 업로드, Firebase Crashlytics 플러그인 등록
  • API에 따라 다른 ProGuard 규칙: 앱끼리 API 버전 통일, API에 맞는 규칙 적용
  • 이름을 문자열 그대로 사용하는 방식 주의: 예) Fragment.class (.class 전체 검색)

@Keep

난독화하면 변수명이 바뀌기 때문에, Gson으로 데이터를 저장·로드하는 코드는 변수 이름이 난독화되어 문제가 생깁니다. 클래스 상단에 @Keep 어노테이션을 추가하고 proguard 규칙을 넣었습니다.

-keep @interface androidx.annotation.Keep
-keep @androidx.annotation.Keep class * {*;} # 멤버 전체 보존
-keepclasseswithmembers class * {
    @androidx.annotation.Keep <fields>;
}
-keepclasseswithmembers class * {
    @androidx.annotation.Keep <methods>;
}
-keepclasseswithmembers class * {
    @androidx.annotation.Keep <init>(...);
}

주의사항과 대응

주의할 곳대응
Enum, API 통신, 상속 코드ProGuard 예외 규칙 추가. 앞으로 구현할 때도 유의해야 해서 데이터로 쓰는 클래스를 한 패키지에 모아 모듈화
Reflection·동적 참조현재 사용하지 않음. 필요하면 @Keep으로 예외 처리
WebView JavascriptInterface난독화되면 웹에서 호출하는 이름이 바뀔 수 있어 주의
Gson·Retrofit JSON 파싱data 클래스를 data 패키지로 모두 옮긴 뒤 proguard 규칙 추가
외부 API·라이브러리각 API 문서의 난독화 규칙 확인
릴리스 빌드난독화는 릴리스 모드에서 동작하므로 릴리스 모드로 확인

Crash 로그 이슈

난독화되면 에러 로그의 클래스·변수 이름도 바뀌어 원인을 바로 확인할 수 없습니다. mapping.txt와 retrace 도구로 원래 이름을 복원할 수 있지만 번거롭고, 에러는 실행 도중에 발생하므로 빌드할 때 미리 걸러지도록 했습니다.

사람과 AI가 놓치는 규칙에 대한 대비 — 빌드 시 검사

proguard 규칙을 추가해도, 이후 새 코드가 추가되면서 규칙을 빠뜨려 에러가 생길 수 있습니다. 그래서 빌드할 때 프로젝트 파일을 탐색해 정규식으로 검사하는 규칙을 만들어 모든 앱에 적용했습니다.

이 검사는 AI 코딩 도구를 위한 안전장치이기도 합니다. 규칙을 문서나 주석으로만 남기면 AI가 놓칠 수 있지만, 빌드를 멈추고 어떤 파일의 어떤 코드가 문제인지 메시지로 알려 주면 AI가 코드를 수정한 뒤 빌드하는 과정에서 스스로 감지하고 고칠 수 있습니다.

apply from: "${rootProject.projectDir}/tools/r8-guard.gradle"

코드 변경 시 확인

  1. 문자열로 클래스·메서드·필드·리소스 이름을 쓰나? → 쓰지 말거나 keep 룰 추가
  2. Gson으로 주고받는 모델인가? → data.model 아래에 두기 (또는 @Keep)
  3. 새 라이브러리를 넣었나? → release 빌드 후 missing_rules.txt 확인
