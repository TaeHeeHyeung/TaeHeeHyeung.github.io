상세 · 셀프증명 코드 최신화 과정 (2026.10, AI 코딩 도구 활용)

AI에 한 번에 맡기지 않고 단계를 나눠 진행했습니다. 단계마다 앱 전체를 테스트해도 최종 Q/A 전에는 어차피 전수 검사가 필요하기 때문에, 단계마다는 Claude가 제시한 테스트 항목을 기준으로 바뀐 부분만 확인하며 빠르게 넘어가고, 최종 Q/A 요청 전에 전수 검사를 직접 한 뒤 Q/A 테스터에게 요청했습니다.

단계한 일이 순서로 한 이유
빌드 기반R8 적용과 빌드 검사(r8-guard), Gradle·AGP·Kotlin 버전 통일, 버전 카탈로그이후 단계를 모두 같은 빌드 기준에서 확인하기 위해
① 에러 수정화면 복원 시 크래시, 여권 크롭 흰 띠 등버그가 있는 코드를 그대로 Kotlin으로 옮기지 않기 위해
② lint메모리 누수(StaticFieldLeak, HandlerLeak), onDraw 안 객체 생성(DrawAllocation), Recycle, Overdraw 등 경고 정리Java 상태에서 위험한 코드를 먼저 줄여, 변환할 때 신경 쓸 것을 줄이기 위해
③ Kotlin 전환작은 패키지부터 9번에 나눠 Java 284개 파일 전환. 빌드 검사(r8-guard)가 .kt 파일도 검사하도록 확장바뀌는 양이 가장 커서, 나눠서 진행하고 단계마다 빌드를 확인하기 위해
④ 코루틴·HiltThread·CountDownLatch를 화면 수명에 맞는 코루틴으로 정리(6단계), Hilt 의존성 주입, 화면 회전 대응. 이 과정에서 Crashlytics 상위 크래시(1위 여권 크롭, 3위 핀치 줌 등)도 수정언어를 바꾼 뒤에야 Kotlin다운 구조로 다듬을 수 있어서
학습 자료Kotlin 유지보수 교육(10장, 퀴즈), Hilt 입문 학습 페이지AI가 바꾼 코드를 개발자가 직접 읽고 고칠 수 있게
검증단계마다: Claude가 제시한 테스트 항목으로 바뀐 부분만 확인
마지막: 전수 검사를 직접 한 뒤 Q/A 테스터에게 최종 테스트 요청		단계마다 전체를 테스트해도 최종 Q/A 전 전수 검사는 어차피 필요해서, 중간 테스트는 바뀐 부분에 집중
